## 0. 약어 및 용어 정의

문서에서 처음 쓰는 약어는 본문에서도 풀어 쓰되, 정의는 이 표를 정본으로 한다.

| 약어 | 원어 | 정의 |
|---|---|---|
| CAN | Controller Area Network | 차량 내부 신호 버스. 자차의 속도·조향각·요레이트·기어 등 **자차 거동의 1차 측정원** |
| 3DOD | 3D Object Detection | 3차원 객체 검출·추적. 주변 객체의 위치·크기·속도·추적 ID 산출 |
| VLM | Vision-Language Model | 영상과 언어를 함께 처리하는 모델. 본 파이프라인에서 시각 의미 해석과 인과 귀속 담당 |
| bbox | bounding box | 객체를 감싸는 사각 영역 좌표. VLM에 "어느 객체를 말하는지" 지시하는 최소 단서 |
| TTC | Time To Collision | 현재 상대속도·거리 기준 충돌까지 남은 시간(초). 위험도 근사 지표 |
| ODD | Operational Design Domain | 시스템이 정상 동작하도록 규정된 운행 조건 범위(도로·기상·시간대 등) |
| SD / SA / MA | Scene Description / Scene Analysis / Meta Action | 장면 묘사 → 상황 분석 → 주행 행동. 자율주행 메타데이터의 통상적 3단 구분 |
| **EPR** | **Error Propagation Rate (오류 전파율)** | **앞 단계의 오류가 뒤 단계 오류로 이어지는 비율.** `P(뒤 단계 오답 \| 앞 단계 오답)` 형태로 측정. 단계별 정확도만으로는 "어디서 무너졌는지"를 알 수 없으므로, 단계 간 오류 연쇄를 따로 측정하는 지표 |
| gold | gold standard | 사람이 판정한 기준 정답 집합 |
| IAA | Inter-Annotator Agreement | 라벨러 간 일치도. 판정 기준의 명확성과 달성 가능 정확도의 상한을 나타냄 |
| ablation | ablation study | 설계 요소를 하나씩 넣고 빼며 기여도를 분리 측정하는 실험 |
| precision / recall | 정밀도 / 재현율 | 붙인 라벨 중 맞은 비율 / 붙였어야 할 것 중 실제로 붙인 비율 |

## 1. 산출물 정의

### 1.1 에피소드 단위

1 episode = **1 ego 거동 사건** = `(ego 거동, 그 거동을 유발한 원인 집합)` 쌍.

- ego 거동은 종·횡을 **병합한 단일 사건**으로 표현. 차량 거동은 연속적 단일 제어 결과이므로 축별 분할하지 않음
- 원인은 **순위 없는 집합**(다중 허용). 지배 원인 선정 없음
- 원인은 **직접 원인만 기록**. 다단 인과(선행차가 보행자 때문에 정지 → ego가 선행차 때문에 정지)에서 근본 원인까지 연결하지 않음
- **원인을 종·횡으로 나누어 귀속하지 않음**
  - 예: "감속하면서 우측으로 차선변경" 에피소드에서 원인이 셋(선행차 감속, 우측 차량, 전방 공사)일 때, 어느 원인이 감속을 유발했고 어느 원인이 차선변경을 유발했는지 **구분하여 기록하지 않는다.** 세 원인 모두 거동 전체에 대응하는 것으로 본다
  - 근거: 실제 주행에서 운전자는 감속과 조향을 하나의 회피 판단으로 수행하며, 사후에 원인별로 분해할 관측 근거가 없다. 분해를 강제하면 판정자 자의에 의존
  - 유보: 인과 정합성 지표의 채점 단위(원인-반응 쌍 개수)에 영향 → KPI 정의서 대조 후 확정 (§9.2)

### 1.2 데이터 계층 — clip · episode · subject

| 계층 | 정의 | 길이·개수 | 비유 |
|---|---|---|---|
| **clip** | 주행 로그의 저장 단위. 영상·CAN·3DOD·map이 함께 묶인 원본 구간 | 20~30초 (데이터셋 의존) | 녹화 파일 1개 |
| **episode** | clip 안에서 ego 거동 사건 하나가 발생한 **가변 길이 구간** `[t_start, t_end]`. 1 episode = 1 태깅 산출물 | clip당 0~수 개 (사건이 없으면 0) | 그 파일 안의 "사건 장면" |
| **subject** | 해당 episode에서 원인 후보로 관측된 개별 객체·요소 (차량·보행자·신호등·정지 차량·도로 기하 등) | episode당 0~수십 개 | 그 장면에 등장한 인물·사물 |

- 하나의 clip에서 여러 episode가 나올 수 있고(예: 20초 안에 감속 1회 + 차선변경 1회 → episode 2개), 사건이 없으면 0개
- 각 episode는 자기 구간의 subject 배열을 갖는다. 같은 차량이 두 episode에 등장하면 **각 episode에 별도 subject 에피소드**로 기록 (track_id로 연결 가능)
- 저장 구조는 episode 단위 2블록:

| 블록 | 담는 것 | 이유 |
|---|---|---|
| episode 공통 | 앵커 시각, 구간 경계, 주행환경(맥락), ego 거동, 인과 링크, 운영 플래그 | episode 전체에 하나만 존재하는 값 — subject마다 반복 기록하면 값이 어긋남 |
| subjects[] | subject별 위치·거동·시각 속성·물리 계측값·신뢰도 | 객체마다 다른 값 |

### 1.3 용도 (이중)

- **학습 데이터 큐레이션** — precision 우선. 오라벨이 학습을 오염
- **평가용 데이터 분포 분석** — recall·무편향 우선. 누락이 분포를 왜곡

두 용도는 요구 정밀도가 상반. **데이터셋을 두 벌 만들지 않고**, episode에 필터링 가능한 메타 플래그를 각인하여 소비 시점에 분리한다(§5).

### 1.3.1 목적 우선순위 — 라벨 품질이 측정 편의에 우선한다

본 파이프라인의 산출물은 **라벨**이지 예측기가 아니다. 태깅 시점에 확보된 정보는 제한 없이 사용하여 해당 클립에 대한 최선의 라벨을 만든다.

- 측정 목적(오류 전파율 분리, 독립성 확보)의 제약이 라벨 품질을 낮춘다면, **측정 쪽을 조정한다** — 표본 한정 이중 실행, 조건 분리 보고 등
- 측정 편의를 위한 제약을 파이프라인 전역 금지로 두지 않는다. 금지로 둘 수 있는 것은 **순환성·재현성처럼 어기면 결과 자체가 무효가 되는 항목**뿐이다
- 사후 정보 사용, 규칙 판정 주입 등 "라벨은 좋아지나 측정이 흐려지는" 항목은 **실험으로 판정**하고, 사용 사실을 산출물에 표기한다

### 1.4 시나리오 유형 라벨 — 확정된 인과 링크 위에 붙는 조합 명칭

**전제 (순서 주의)**: 유형 라벨은 인과를 **판정하지 않는다.** S3에서 인과 링크가 확정된 뒤, 그 링크 위에 붙는 조회용 명칭이다. 라벨 규칙이 원인을 고르는 것이 아니다.

**왜 필요한가**: `끼어들기` / `급끼어들기` / `합류부 끼어들기`처럼 유형 명칭을 어휘 코드로 두면 세부가 곱으로 증가하고, 판정자·VLM이 그중 하나를 고르게 되어 불일치가 커진다. 따라서 어휘에는 관측 항목만 두고, 유형 명칭은 조합 규칙으로 조회 시점에 산출한다.

**쌍 구조와의 대응** (§1.1): 에피소드는 `(ego 거동, 원인 집합)` 쌍이므로, 유형 라벨도 두 조각으로 구성한다.

| 조각 | 정의 근거 | 예 |
|---|---|---|
| 원인 측 라벨 | 인과 링크된 subject의 위치 × 거동 (+계측값) | 끼어들기, 선행차 감속, 보행자 횡단, 적색신호 정지, 정지차량 차로 점유 |
| ego 측 라벨 | ego 거동 (종·횡 transition) | 자차 감속, 자차 정지, 자차 차선변경, 자차 회피 |
| 표시 명칭 | 두 조각의 **템플릿 결합** | "선행차 감속 → 자차 감속" / "우측 끼어들기 → 자차 감속·좌측 이동" |

- 코드 수는 곱이 아니라 **합**으로 증가 (원인 측 N + ego 측 M)
- 검색은 두 축 AND — "끼어들기인데 자차가 무반응" 같은 질의는 구조상 성립하지 않음(무반응이면 에피소드 자체가 없음, §2.1의 구조적 배제)

**태깅 시 유형 명칭을 고르지 않는다** — VLM 프롬프트와 정답셋 판정 항목은 관측 항목만 사용한다. 유형 명칭을 판정 항목에 넣으면 위 문제가 그대로 재발한다.

**산출 의존성 표기** — 라벨이 어떤 소스에 의존하는지 함께 기록한다. 관측값이 확정된 뒤 라벨 계산 자체는 결정론적이지만, **입력 관측값의 출처는 라벨마다 다르다.**

| 구분 | 조건에 쓰이는 항목 | 예 |
|---|---|---|
| rule-only | 위치·객체 거동·계측값 (3DOD·map·CAN) | 끼어들기, 선행차 감속, 근접 통과 |
| map-dependent | 차선 귀속 필요 — map 무효 시 근사 강등 | 차로 기반 위치가 조건인 전체 |
| vlm-dependent | 등화·신호·표지·의도 단서 포함 | 적색신호 정지, 양보 의도, 문 열림 |

- 2계층: 기본형(관측 항목만) / 세부형(기본형 + 계측값 임계). **임계 미확정 시 세부형 비활성**
- 유형 세분화는 어휘 개정이 아니라 계측값·시각 속성 **기록률 상승**으로 가능해짐

### 1.5 상류 단계 (클립 선별)와의 연결 — 조건부

대량 데이터에서는 선별 단계를 거친 클립에 본 파이프라인을 적용하고, **데이터 규모가 작으면 선별 없이 전수 처리한다. 선별은 의무 사항이 아니다.**

- 선별을 거친 경우에만 `selection_score`·`selection_rank`·`selection_version`·`selection_reason` 기재
- 전수 처리인 경우 `selection_applied = false` — 이 플래그가 없으면 나중에 분포 분석 시 선별 편향 유무를 판별할 수 없음
- 선별을 거친 데이터와 전수 처리 데이터를 **같은 분포 분석에 섞지 않는다** (모집단이 다름)
- `difficulty` (1~10)는 선별 여부와 무관하게 episode 단위로 기록 — long-tail 큐레이션의 직접 신호

## 2. 파이프라인 구조 (확정)

### 2.1 방향 — Action-first

CAN 거동 transition으로 앵커를 먼저 확정 → 해당 구간에서 원인 후보를 탐색·선정.

**확보되는 것**: 앵커의 모델 비관여(순환성 차단) / 결정론적 트리거(재현성) / 원인 탐색 범위 한정(처리량 예측)

**구조적으로 배제되는 것** — 설계 한계로 명시 기록:
- **반응 없는 원인** — 위험이 존재했으나 ego가 무반응인 구간은 에피소드가 생성되지 않음. 안전 관점의 중요 구간이 데이터에서 누락됨. 범위 밖으로 명시 배제하거나, cause-first 소규모 보완 트랙을 별도 운영
- **선점 행동** — 조기 감속으로 위험이 실현되지 않은 경우, 원인의 관측 근거가 약해 오귀속 위험
- **점진적 거동** — transition이 뚜렷하지 않아 미검출 또는 다중 검출

### 2.2 단계 정의와 단계별 설계 변수

| 단계 | 하는 일 | 사용 소스 | 산출 | 이 단계에서 정해야 하는 설계 변수 |
|---|---|---|---|---|
| **S0 앵커 검출** | 자차 거동이 바뀌는 시점을 찾아 에피소드의 기준 시각 확정 | CAN 규칙 (경로 유형 라벨은 지도∪VLM 해소 — §2.3) | `key_frame_t`, 종방향 거동, 경로 전이 트리거 | 전이 검출 임계 (§7.1) — 임계가 곧 에피소드 모집단 정의 |
| **S1 물리 사실 추출** | 규칙으로 계산 가능한 사실 산출 | 3DOD + 정밀지도 + CAN | 차선 귀속, 자차 기준 위치, 객체 거동, 물리 계측값, **원인 후보 집합** | **DV-1 물리 정보 가공 수준** / **DV-2 원인 후보 개방성** / 시간창 경계 규칙(§2.4) / 후보 범위 임계(§4.4) |
| **S2 시각 의미 추출** | 규칙으로 알 수 없는 시각 정보 판독 | VLM 1차 호출 | 등화류·신호·표지·노면·가시성·의도 단서 | **DV-3 입력 구성 방식** / 프레임 샘플링(§2.5) / 뷰 조합(§3.3) / bbox 표현(§2.7) / 예산 배분(§3.4) |
| **S3 인과 귀속** | 후보 중 실제 원인을 선정 | VLM 2차 호출 | 원인 집합 확정, 신뢰도 | 신뢰도 임계(미해결 처리 기준, §4.4) / 생성 순서(§5) |

**S1과 S2는 병렬이며 S3에서 합류한다.** 순차 체인이 아니라 수렴 구조다.

- 따라서 **오류 전파율(EPR)은 하나가 아니라 두 경로**로 측정한다: S1→S3(물리 사실의 오류가 인과 판단으로 전파), S2→S3(시각 판독의 오류가 인과 판단으로 전파)
- 통상적인 SD→SA→MA 선형 체인과 형태가 다르므로, 지표 정의서에 이 차이를 명시해야 한다
- S2 입력의 **기본값은 최소 단서**(객체 ID와 bbox)다. S1 판단을 넘기면 두 경로의 독립성이 약해져 전파율 측정 해상도가 떨어지기 때문이다
- 단 이는 **금지가 아니라 기본값**이다(§1.3.1). 규칙 판정 주입이 라벨 정확도를 실제로 높이면 주입 쪽을 채택하고, 전파율은 표본 한정 독립 실행으로 별도 측정한다 → 실험 C에서 판정

**잔여 오염 경로(기록)**: bbox 자체가 3DOD 산출물이므로, S1이 놓친 객체는 S2에도 나타나지 않는다. 대응안(S2에 "후보 외 시각적 주목 대상" 자유 슬롯 부여)은 실험 항목으로 처리(§3.2).

### 2.3 앵커 (S0) — 검출과 라벨 해소의 분리

**핵심 구분**: 앵커의 규칙 기반성은 **전이 시점 검출**에 대한 것이지, 거동 유형 라벨 전체에 대한 것이 아니다.

| 구성 | 산출 방법 | 근거 |
|---|---|---|
| `key_frame_t` (전이 시점) | **CAN 규칙 확정. 모델 비관여** | 순환성 차단의 핵심 — 이 지점만 지키면 앵커 오염이 없음 |
| 종방향 거동 (가속·감속·정지·서행) | **CAN 규칙 확정** | 속도·가속도에서 직접 판별 |
| 경로 유형 (좌/우회전·차선변경·U턴) | **CAN이 전이만 트리거 + 라벨은 지도 ∪ VLM으로 해소** | CAN 요레이트만으로는 교차로 회전 / 도로 곡률 / 분기 / U턴이 구분되지 않음 (under-determined). 지도 없이 CAN만으로 U턴을 판별할 수 없다는 것은 실측으로 확인된 제약 |

- 즉 **"자차 거동은 rule anchored"의 정확한 의미**는 "전이 시점과 종방향은 규칙 확정, 경로 유형은 맥락 해소"다. 모든 거동 유형이 CAN만으로 확정되지는 않는다
- 경로 라벨 해소에 VLM이 관여하더라도 **앵커(시점)는 오염되지 않는다** — 순환성 차단은 시점 확정에 걸려 있고, 라벨 해소는 그 뒤 단계
- ego 거동은 **전이 + 결과 상태 병기**: 결정론적 귀결이 아닌 조합(감속 개시 → 정지 아님)이 존재하므로 중복이 아니며, 두 필드의 정합성 검사가 자동 검증 항목이 됨
- transition 검출 임계는 **에피소드 모집단을 정의**하므로 에피소드에 각인(임계 변경 = 데이터셋 변경)
- 경로 유형 라벨은 규칙 확정값이 아니므로 **평가 대상**이며, 기계 채점 기준(AUTO_GT)으로 사용 금지

### 2.3.1 전이 검출 규칙 — 무엇을 사건으로 볼 것인가

앵커는 "자차 거동이 바뀐 시점"인데, 주행 신호에는 **사건이 아닌 변화**가 끊임없이 섞인다. 도로 곡률을 따라가는 조향, 차로 내 미세 흔들림, 노면 요철에 의한 속도 변동, 정체 구간의 가다서다. 이를 걸러내지 못하면 에피소드가 폭증하고 모집단 자체가 무의미해진다.

**판정 구조 — 4중 필터** (임계값은 §7.1, 구조는 여기서 고정)

| # | 필터 | 거르는 대상 | 판정 신호 |
|---|---|---|---|
| 1 | **크기** | 미미한 변동 | 종방향은 속도 변화량·감속도, 횡방향은 누적 방위 변화량(순간 요레이트 아님) |
| 2 | **지속** | 순간적 흔들림 | 변화가 최소 지속시간 이상 유지되는가. 짧은 스파이크는 사건 아님 |
| 3 | **곡률 보정** | 도로를 따라가는 조향 | 자차 방위 변화에서 **도로 기하가 설명하는 몫을 뺀 잔차**로 판정. **task_episode(Stage2, map 있음)**은 차로 중심선 곡률로 수치 잔차 계산(규칙 전용). **task_selection(Stage1, map 없음)**은 수치 보정 대신 애매 구간 후보만 VLM에 조향-기인/도로형상-기인 여부를 직접 확인(`vlm_confirmed`) — 거동+VLM 조합, 기존 반응성 확인(`vlm_window`)과 동일 패턴 |
| 4 | **병합** | 사건의 분절 | 같은 방향의 전이가 짧은 간격으로 이어지면 1건으로 병합(가다서다 대응). 반대 방향 전이는 병합하지 않음 |

**설계 근거**
- 순간 요레이트가 아니라 **누적 방위 변화량**을 쓰는 이유: 완만한 대곡선과 급한 소회전이 순간값으로는 구분되지 않는다
- 곡률 보정이 3번인 이유: 1·2번만으로는 곡선로 주행이 전부 회전 전이로 잡힌다. **`common/events.py::detect_events()`는 Stage1·Stage2가 공유하는 map-free 함수이므로 보정 로직을 그 안에 넣지 않는다** — 소비 단계에서 각자의 가용 신호로 보정한다: Stage2는 `map_lane.py`(차로 중심선)로 규칙 보정, Stage1은 map이 없으므로 애매 구간만 VLM 확인으로 대체. **보정 방식(map/vlm_confirmed/estimated/none)을 에피소드에 기록**
- 병합은 마지막: 앞 단계에서 살아남은 전이끼리만 병합해야 미미한 변동이 병합으로 되살아나지 않는다

**기록 의무**
- `transition_filters_passed`: 통과한 필터와 각 판정값
- `curvature_correction_source`: `map` / `vlm_confirmed` / `estimated` / `none`
- `merged_from`: 병합된 원래 전이 수

**한계 명시**: 4중 필터를 통과하지 못한 변화는 에피소드가 생성되지 않는다. 완만하게 진행된 실제 사건(점진적 감속으로 정지)이 누락될 수 있으므로, **필터 통과 직전에서 탈락한 경계 사례를 별도 로그로 축적**하여 임계 조정 근거로 사용한다

### 2.3.2 규칙 불확실성 신호 — 규칙이 흔들리는 지점 찾기

S1의 판정이 항상 옳지는 않다. 지도가 무효이거나, 객체가 차로 경계에 걸쳐 있거나, 검출이 불안정한 구간에서는 규칙 산출값 자체가 의심스럽다. 이를 **VLM 호출 전에 결정론적으로** 판별하는 신호다.

| 신호 | 무엇으로 계산하는가 | 출력 |
|---|---|---|
| **지도 유효성** | 자차 차로 경계쌍이 안정적으로 검출되는지 — 경계 간 폭이 정상 범위이고 창 내 일정 비율 이상 유지되는가 | `valid` / `fallback` |
| **기하 여유** | 판정 경계까지의 거리를 차로 폭으로 정규화. 객체 횡위치가 차로 경계에 근접할수록 "같은 차로 / 인접 차로" 판정이 불안정 | 0~1 (작을수록 불확실) |
| **검출 품질** | 창 내 관측 프레임 비율, 프레임 간 박스 위치·크기 변동폭, 다른 객체와의 겹침 정도 | 0~1 |
| **소스 상충** | 같은 값을 두 경로로 구했을 때 불일치 — 코리도어 근사 판정 ↔ 지도 기반 판정, 횡변위 부호 ↔ 차로 인덱스 변화 | 불일치 항목 수 |
| **시계열 흔들림** | 창 내에서 판정 라벨이 바뀐 횟수 (같은 차로 ↔ 인접 차로 왕복 등) | 변경 횟수 |

**세 가지 용도**
1. **주입 제어** — 임계 초과 객체는 `gt_before`에서 제외하거나 "자동 검출값, 오차 가능" 주석 부착 (§3.1 DV-8)
2. **VLM 라우팅** — 신호가 전부 잠잠하면 규칙 판정을 확정하고 VLM 질의를 생략, 하나라도 켜지면 VLM에 확인 요청
3. **신뢰도 원료** — 최종 신뢰 점수의 후보 신호 (규칙 측 확신도)

**v1 운용 권장**: 5개를 동시에 튜닝하면 근거 없는 상수가 5개 늘어난다. **지도 유효성(이미 구현)과 기하 여유(구현 반나절)** 2개만 가동하고 나머지 3개는 값만 기록해 분포를 축적한다.

### 2.4 시간창 — VLM에게 보여줄 구간

에피소드마다 "몇 초짜리 영상을, 몇 프레임으로 보여줄 것인가"를 정하는 규칙이다.

**(1) 창은 사건 전체를 담는다**

```
window_start ─────── key_frame_t ─────── window_end
 (원인 발생 이전)      (거동 개시)        (거동 완료 이후)
```

- **시작점**: 사건 기준 역방향 확장 — 직전 자차 거동 전이, 또는 원인 후보의 상태 변화 시점(감속 시작·차로 진입 개시) 중 먼저 만나는 지점까지
- **끝점**: 자차 거동이 **완료되어 안정 상태에 들어간 시점**. 거동 개시 시점(`key_frame_t`)에서 끊지 않는다
- 끝점을 거동 개시에서 끊으면 안 되는 이유:
  - 자차 주행 경로(ego-path)가 절반만 기록되어 **학습 가치가 있는 에피소드로 성립하지 않음** — 큐레이션 산출물의 용도와 배치
  - 원인-반응의 연결이 중간에서 잘려 인과 라벨의 근거 구간이 불완전해짐
  - 결과 상태(`resulting_state`)와 회피 궤적이 창 밖에 놓임
- `window_start`·`key_frame_t`·`window_end`를 기록하고, **경계 사유는 시작·끝을 분리**한다
  - `window_start_reason`: `prev_ego_transition`(직전 자차 전이) / `candidate_state_change`(원인 후보 상태변화) / `budget_truncation`(예산 절단)
  - `window_end_reason`: `maneuver_complete`(거동 완료·안정화) / `next_transition`(다음 전이 개시) / `clip_end`(클립 종료) / `budget_truncation`
  - 단일 필드로 두면 사유가 어느 경계의 것인지 판별할 수 없다

**(2) 판정에는 창 전 구간을 사용한다**

- 인과 귀속을 포함한 모든 필드 판정에 **`key_frame_t` 이후 구간을 제한 없이 사용**한다. 태깅 시점에 이미 확보된 정보를 쓰지 않을 이유가 없으며, 목적은 해당 클립에 대한 최선의 라벨이다
- 거동 완료 이후 구간은 인과 판정의 정확도를 실제로 높인다 — 결과 상태, 회피 궤적, 원인 객체의 후속 거동이 모두 판정 근거가 된다
- **소비 단계 주의사항**(파이프라인 제약 아님): 인과 라벨은 사후 정보를 포함해 판정된 값이다. 이 라벨을 예측 모델 학습에 쓸 경우, 추론 시점에는 없는 정보에 근거한 패턴을 학습할 수 있다 → **export 문서에 명시**하고, 필요 시 소비 측에서 시점 제한 재라벨을 수행

**(3) 창 길이와 프레임 예산은 교환 관계다**

같은 토큰 예산에서 **긴 창 × 낮은 프레임률** ↔ **짧은 창 × 높은 프레임률**이 경합한다.

- 예: 10초 창을 2 fps로 담으면 20프레임, 4초 창을 5 fps로 담아도 20프레임
- 긴 창은 원인의 발단과 거동 완료를 모두 담지만 순간 변화(끼어들기 진입 순간)를 놓치고, 높은 프레임률은 반대
- **고정 방식 vs 자차 거동에 따른 적응 방식** 중 어느 쪽이 나은지는 실험으로 확인 → 설계 변수 **DV-2**(§3.1)

## 3. 설계공간 — 무엇을 바꿔볼 것인가, 무엇이 아직 안 정해졌나

설계 변수(Design Variable, **DV**)는 값을 바꾸면 파이프라인 동작이 달라지는 선택지다. 각 DV에는 **어느 단계에 속하는지**를 표기한다.

### 3.0 이미 확정한 것

| 항목 | 단계 | 확정 내용 | 근거 |
|---|---|---|---|
| 방향 | 전체 | Action-first | 앵커 순환성 차단·재현성 (§2.1) |
| 앵커 산출 | S0 | **전이 시점·종방향 = CAN 규칙 확정 / 경로 유형 라벨 = 지도 ∪ VLM 해소** (§2.3) | CAN 요레이트만으로 회전·곡률·분기·U턴 구분 불가 |
| 원인 후보 개방성 | S1→S3 | **C3 hybrid 확정** — 후보 목록 내에서 원인 선택 + "목록 밖에 원인 있음" 표시만 허용 | 채점 명확성을 유지하면서 규칙 누락을 탐지. C1은 누락을 영구 은폐, C2는 채점 불가 |
| 프레임 선택의 순환 배제 | S2 | **기본 샘플링은 후보 비의존**(균등·계층). 후보 상태변화 시점 기반 **추가 프레임은 플래그 기록 후 허용** | 기본까지 후보 의존이면 규칙이 놓친 원인은 프레임이 없어 영영 발견 불가. 추가분만 허용하면 라벨 품질을 얻으면서 누락 탐지 경로는 유지 — 단 recall 평가 시 조건 분리 보고 |
| 뷰 선택의 순환 배제 | S2 | 후보 방위로만 뷰를 **좁히지** 않음. 장면 구조(도로 기하·객체 밀도) 기반 확대는 허용 | 동일 논리 — 축소는 누락을 만들고 확대는 만들지 않음 |

### 3.1 실험으로 확정할 설계 변수

#### DV-1. 물리 정보 가공 수준 (S1 → S2/S3)

규칙(3DOD·정밀지도·CAN)이 계산한 정보를 **어느 정도 가공해서** VLM에 넘길 것인가.

| 수준 | 넘기는 것 | 예 |
|---|---|---|
| L0 원측정값 | 숫자 그대로 | 상대거리 18.3m, 상대속도 −4.2m/s, 횡오프셋 1.7m |
| L1 파생 판단 | 규칙의 1차 판단 | "선행 차량 감속 중, 자차 차로로 진입 중" |

- **바뀌는 것**: 규칙과 VLM의 판단 분담 경계. L1일수록 VLM은 확인만 하게 되고 규칙 오류가 그대로 전파
- 요약 문장(L2)은 정보 손실이 명백하여 제외

#### DV-2. 시간창 길이 × 프레임률 (S2 입력)

| 수준 | 방식 |
|---|---|
| F1 고정 | 창 길이·프레임률 상수 (예: 8초 · 2 fps) |
| F2 적응 | 자차 거동 유형·지속시간에 따라 창과 프레임률 조정 (짧은 급제동 = 고프레임률, 긴 합류 = 장창) |

- **바뀌는 것**: 원인 유형별 관측 가능성. 순간 사건과 장기 사건 중 어느 쪽이 유리한지가 뒤집힘
- 적응 방식은 자차 거동(규칙 산출)에만 의존해야 함 — 원인 후보에 의존하면 순환(§3.0)

#### DV-3. 뷰 선택 (S2 입력)

| 수준 | 방식 |
|---|---|
| V1 고정 뷰셋 | 전 에피소드 동일 뷰 조합 |
| V2 GT 기반 적응 라우팅 | **3DOD·정밀지도로 확인된 객체 분포·도로 기하**에 따라 뷰 선택 (교차로 = 좌우 추가, 직선 추종 = 전방 집중) |

- **바뀌는 것**: 토큰 예산의 배분 효율
- V2의 조건은 **개별 원인 후보가 아니라 장면 구조**(도로 기하, 객체 밀도 분포)에 근거해야 순환을 피함 — "규칙이 지목한 원인 방위"를 조건으로 쓰면 §3.0 위반
- 선행 작업: 누적 뷰 실험(전방 → +전방좌우 → +좌우 → +후방좌우 → +후방)으로 원인 유형별 한계 기여 곡선을 얻고, 그 곡선이 V2 라우팅 규칙의 근거가 됨

#### DV-4. 영상 입력 사양 (S2, vision encoder)

- 프레임 해상도, 다중 뷰 배치 방식(개별 프레임 vs 몽타주 합성), bbox 표현(오버레이 렌더링 vs 좌표 텍스트), bbox 시계열 압축(시작·종료 좌표만 vs 전 프레임)
- **바뀌는 것**: 동일 토큰에서 담기는 시각 정보량. 신호·표지 판독은 해상도, 끼어들기 판별은 시간 해상도에 지배됨
- 추적 ID는 창 전체에서 유지되어야 함 — ID 일관성이 깨지면 S2·S3 결합 불가 (제약이지 변수가 아님)

#### DV-5. 텍스트 입력 구성 (S2/S3, text encoder)

- DV-1이 "무엇을 넘기나"라면 DV-5는 **"어떤 형식으로 넘기나"**
- 후보: 표 형식 / 키-값 나열 / 자연어 문장 / JSON. 단위·좌표계 표기 규약, 후보 나열 순서(거리순·검출 신뢰도순·무작위 — 순서 편향 확인 필요)
- **바뀌는 것**: 동일 정보의 파싱 정확도. long-context에서는 배치 위치 효과도 발생

#### DV-6. 프롬프팅 규칙 (S2/S3)

- 질의 분할 단위(한 번에 전 필드 vs 필드군별 분할), 선택지 제시 방식(개방형 vs 열거형), 출력 형식 강제 방법(JSON 스키마 강제 vs 자유 생성 후 파싱), few-shot 예시 유무·개수, 자유 추론(`<think>`) 허용 여부
- **바뀌는 것**: 출력 파싱 성공률과 판정 일관성. 열거형은 일관성이 높고 개방형은 누락 탐지에 유리

#### DV-7. 중간 산출물 외부화 (S2·S3 구조)

| 수준 | 방식 |
|---|---|
| P1 2-pass 분리 | 시각 판독(S2) 결과를 **파일로 저장**한 뒤, 별도 호출에서 인과 귀속(S3) |
| P2 단일 pass | 영상+단서를 한 번에 주고 원인까지 산출 |

- **질문에 대한 답 — 단일 pass도 내부적으로는 유사한 추론을 거치지 않는가**: 그렇다. 차이는 모델 내부 연산이 아니라 **외부에서 관측·개입 가능한 지점의 유무**다.
  1. **채점 가능성**: P1은 시각 판독 결과가 파일에 남아 gold와 대조 가능 → S2 정확도와 S3 정확도를 분리 산출. P2는 내부 추론이 남지 않아(`<think>`를 켜도 그 내용이 실제 계산 경로라는 보장 없음) 오류 위치 특정 불가
  2. **오류 전파율(EPR) 측정**: P1에서만 S2→S3 전파율이 정의됨. P2는 두 오류가 합쳐진 값만 관측
  3. **개입 지점**: P1은 S2 출력을 규칙으로 검사·보정한 뒤 S3에 넣을 수 있음. P2는 불가
  4. **비용**: P2가 호출 1회 적고 지연도 짧음
- 즉 P1의 이점은 성능이 아니라 **측정 가능성과 통제 가능성**이며, 이것이 본 과제(신뢰도·전파율 평가)의 목적과 직결


#### DV-8. S1 물리 정보의 S2 주입 (S1 → S2)

S1이 계산한 정보 중 **무엇을 VLM 프롬프트에 넣을 것인가**. §6.1의 조건화 방향 때문에 위치(영상 앞/뒤)와 포함 여부가 함께 결정된다.

**판정 기준 3**
1. VLM이 그 정보 없이 질문에 답할 수 있는가 — 없으면 주입(grounding 목적)
2. 주입하면 VLM이 그 값을 그대로 베끼는가 — 베끼면 애초에 VLM 호출이 불필요(`gt_only`로 강등)
3. 주입이 VLM의 독립 판단을 편향시키는가 — 편향되면 미주입

**필드 단위 배정** (기본값. 실험 C로 확정)

| 클래스 | 필드 | 근거 |
|---|---|---|
| **gt_only**<br>호출 없음 | 자차 속도·가속도·요레이트 / 객체 거리·방위 / 차로 ID / 지도 유래 도로 기하 / 계측값 전량(간격·TTC·감속도·측방 여유·정지 지속) | 규칙 산출값이 최종값. 기준 2 — 주입해도 복사만 발생 |
| **gt_before**<br>영상 앞 | 객체 목록(ID·종류·좌표·속도) / 자차 기준 위치 / 객체 거동(정지·감속 등) / 자차 거동 전이 | 기준 1 — 좌표 기반 객체 지목은 영상만으로 실패율이 높다. "id=42"라는 참조를 성립시키는 최소 grounding |
| **gt_free**<br>미주입 | 등화류·차량 표식·노면 상태·가려짐·의도 단서·보행자 자세·시선 / 날씨·조명·시간대·도로 유형·장면 유형 | 기준 3 — 시각에만 존재하거나(전자), 규칙 판정이 편향을 유도(후자) |

**gt_before 블록의 작성 규칙**
- **관측 사실만 적는다**: 위치·속도·크기·ID. "감속 중"까지는 관측이지만 "위험하다"·"끼어드는 중"은 판정이므로 제외
- 불확실 객체 표기: `rule_uncertainty` 임계 초과 객체는 "자동 검출값, 오차 가능" 주석을 부착하거나 목록에서 제외
- 지도 무효 구간에서는 차로 기준 위치 대신 코리도어 근사임을 명시

**영상 뒤 주입(gt_after)을 기본값으로 두지 않는 이유**
- 도입 근거였던 "모델이 규칙과 다른 값을 낼 여지를 남겨 모순을 탐지"는 **주입 없이도 성립**한다 — VLM 독립 실행 후 규칙 판정과 사후 대조하면 동일 신호를 얻고 토큰 비용이 낮다
- 단 이는 금지가 아니라 기본값 선택이다(§1.3.1). 실험 C에서 라벨 정확도 이득이 확인되면 채택

#### DV-9. 필드별 추론 경로 (전 단계)

| 경로 | 조건 | 실행 |
|---|---|---|
| `gt_only` | 규칙 산출값이 최종값 | VLM 미호출 |
| `scored` | 값 집합이 닫혀 있음 | 후보 점수화 (decode 0회) |
| `generated` | 자유 서술 | decode |

- **`rule_derivable`과 `gt_only`는 다른 개념**이다. 전자는 "규칙으로 산출 가능한가"(정의 속성), 후자는 "VLM을 호출하는가"(실행 결정). 규칙 산출이 가능해도 검증 목적으로 호출할 수 있으므로 겹치되 같지 않다 → 별도 필드
- **점수화 방식 선택**: 후보를 각각 이어붙여 확률을 합산하는 **시퀀스 점수화를 기본값**으로 한다. 한 위치의 분포만 읽는 방식(first-token)은 후보들의 첫 토큰이 같으면 판별이 불가능한데, 실측 결과 충돌의 대부분이 **좌/우 쌍**(`lane_change_left_onset`·`lane_change_right_onset` 등 38개 값)이어서 최상위 실패 모드에서 판별력을 잃는다. first-token 방식은 충돌 없음이 검증된 필드에 한해 빠른 경로로 허용
- **자유 서술의 위치**: 서술은 에피소드 전 구간을 대상으로 하므로 점수화로 대체 불가. **구조 필드를 모두 확정한 뒤 decode 1회로 초안 생성**한다. 서술이 확정 라벨에 조건화되므로 §7의 순서 원칙(관측 → 판단 → 결정 → 서술)과도 일치

### 3.2 실행 순서

0. **DV-9 필드 경로 분류 확정** — DV-8·조건화 강도·신뢰도 정의가 전부 여기 의존하므로 선행
1. **DV-1 × DV-7 교차** (2×2) — 판단 분담 경계와 측정 구조의 상호작용 확인. DV-1의 L1은 P1의 이점을 일부 흡수하므로 교차항 필수
2. 승자 조건에서 **DV-2 → DV-3 → DV-4** 순 (입력 예산 계열: 창·뷰·해상도가 같은 토큰을 두고 경합하므로 이 순서로 포화점 확인)
3. **DV-5 · DV-6**은 gold 소표본에서 2~3안 비교 (전 조건 교차 불요)

### 3.3 예산 배분 trade-off (S2)

같은 토큰 예산에서 세 방향이 경합: **뷰 수 ↑ / 시간 해상도 ↑ / 공간 해상도 ↑**

- 끼어들기 판별은 시간 해상도, 신호·표지 판독은 공간 해상도, 측방 원인 포착은 뷰 수가 지배적
- **원인 유형마다 최적 배분이 다르다** → 단일 고정 배분은 특정 유형을 체계적으로 불리하게 만들고, 그 편향이 평가용 분포 분석에 전이됨. 배분 결정 시 유형별 영향 병기 보고

### 3.4 하이퍼파라미터 (실측 후 선언 — 실험 대상 아님)

값을 정하는 문제이지 구조를 고르는 문제가 아니다. 분포 실측 후 선언하고 `threshold_set_id`로 버전 관리한다.

- transition 검출 임계 (감속·조향 개시 판정) — 에피소드 모집단을 정의하므로 변경 = 데이터셋 변경
- 반응 지연 하한·상한 — 원인 유형별 분포가 다르므로 상수가 아니라 gold 실측에서 결정
- 창 상한(lookback 깊이), 후보 필터 임계(거리·TTC), `unresolved` 신뢰도 임계, 동시 전이 판정 허용 시차
- 시나리오 세부형 라벨 임계 (급끼어들기 진입 횡속도 등)

## 4. 준거 및 지표 — 무엇을 위해 필요한가

**목적**: 설계 변수의 우열을 판정하려면 "무엇이 더 나은가"를 재는 자가 있어야 한다. §4는 그 자를 정의한다. 두 종류를 쓴다 — **기계가 전수 검사하는 물리 필요조건(B)**과 **사람이 만든 기준 정답(A)**이며, B는 틀린 것을 걸러낼 뿐 맞았음을 증명하지 못하므로 최종 판정은 A가 한다.

### 4.1 준거 B — 물리 필요조건 자동 검사 (전수, S1·S3 산출물 대상)

인과 라벨이 **물리적으로 가능한가**를 기계가 전수 검사한다. 통과는 정답을 뜻하지 않는다.

| 검사 | 입력 | 판정 로직 | 위반 시 |
|---|---|---|---|
| **시간 순서** | 원인 객체의 상태변화 시각 `t_c`, `key_frame_t` | `t_c < key_frame_t`. 원인이 결과보다 늦을 수 없음 | 오답 확정 |
| **반응 지연** | `key_frame_t − t_c` | 하한 미만이면 사람이 인지·반응할 수 없는 간격, 상한 초과면 인과로 보기 어려운 간격. 하한·상한은 원인 유형별로 다름(신호 대기는 길고 끼어들기는 짧음) | 오답 확정 |
| **기하 정합** | 원인 객체 위치, 자차 진행 경로 | 원인이 자차 경로 또는 관련 인접 영역 내에 있는가. 반대편 차로 뒤쪽 객체는 감속 원인이 될 수 없음 | 오답 확정 |
| **근접성** | 간격·TTC·측방 여유 | 판정 범위(§5.1 후보 범위) 내에 있는가 | 오답 확정 |
| **가시성** | `camera_visible`, 센서 관측 여부 | 어느 센서로도 관측되지 않은 객체는 원인이 될 수 없음. 카메라 비가시·LiDAR 검출만 된 경우는 통과시키되 **플래그 유지** | 비관측이면 오답 확정 |
| **유형-방향 정합** | 원인 유형, 자차 거동 방향 | 예: 좌측 회피인데 원인 객체가 우측에만 있으면 위반. 신호 정지인데 신호 통제 요소가 관측되지 않으면 위반 | 오답 확정 |

**판정 출력은 두 값뿐이다** — `오답 확정` / `미판정`. **`정답` 판정은 내리지 않는다.**

- 필요조건이므로 통과했다고 인과가 성립하는 것이 아니다. **B 통과율을 정확도로 보고하는 것을 금지**한다
- 위반 시 라벨을 삭제하지 않는다. 위반 사실과 위반 항목을 에피소드에 기록하여 오류 유형 분류(§4.4)와 재라벨 우선순위에 사용한다
- 반응 지연의 하한·상한은 원인 유형별 gold 실측에서 도출한다(§7.1). 단일 상수로 두면 특정 유형이 체계적으로 탈락한다

### 4.2 준거 A — 사람 기준 정답(gold), 층화 표본

- 전 필드 포함, 점진 축적. 결측 필드 보강형
- **단계별 채점** — 최종 인과 쌍만이 아니라 S1 물리 사실, S2 시각 의미를 각각 판정. 라벨링 공수가 단계 수만큼 증가하므로 표본 규모 재산정 필요
- 층화 우선순위: 원인 유형별 최소 표본 → B 미판정 구간 → 조건 간 불일치 구간 → **무작위 대조군**(소량이라도 필수, 없으면 전체 정확도 추정 불가)
- **gold 자체의 신뢰도 선측정** — 초기 소표본에 2인 독립 라벨로 일치도(IAA) 산출. 이 수치가 파이프라인 정확도의 실질 상한
- **복수 정답 허용** — 판단 전용 필드(의도 단서·제스처·관련성)는 허용 정답 집합으로 채점. 단일 정답 강제 시 일치도 하락이 태그 결함이 아니라 채점 구조 문제로 나타남
- blind 라벨링(자동 태그·점수 비노출)

### 4.3 지표 — 단계별 정확도 + 오류 전파율(EPR)

- 단계별 정확도: S0 / S1 / S2 / S3 각각
- **오류 전파율(EPR)**: S1→S3, S2→S3 두 경로 분리 산출 (수렴 구조이므로 단일 값이 아님)
- **조건부·무조건부 병기** — S3 정확도를 "S1·S2 모두 정답인 경우로 한정"한 값과 전체 값을 모두 산출. **두 값의 차이가 곧 EPR**

### 4.4 오류 유형 분류 (gold 채점 전 고정)

| 코드 | 유형 | 귀속 단계 |
|---|---|---|
| ERR-ANCHOR | transition 검출 오류·점진 거동 미검출 | S0 |
| ERR-FACT | 3DOD 좌표·속도 오류 | S1 |
| ERR-MAP | 지도 정합 실패로 인한 차선 귀속 오류 | S1 |
| ERR-VISUAL | 등화류·신호·표지 오독 | S2 |
| ERR-ATTRIB | 사실은 정확하나 인과 귀속이 오답 | S3 |

사후에 정의하면 조건 간 비교가 불가하므로 채점 시작 전 고정한다.

### 4.5 원인 없음·미해결의 채점 취급 (S3)

- `none`(원인 없음) — 물리 게이트 후보 공집합. 정오 판정 대상
- `unresolved`(특정 실패) — 신뢰도 임계 미만. 오답으로 볼지 기권으로 볼지에 따라 조건 순위가 바뀌므로 **커버리지-정확도 곡선**으로 보고
- 신뢰도 임계가 하이퍼파라미터이므로 임계 스윕이 곧 calibration 평가
- 두 값의 발생률을 조건별 필수 보고 항목으로 고정 (회피 경로 남용 탐지)

### 4.6 분포 관련 보고 요구

- 원인 유형 분포는 극단적 불균형 예상 → 표본 미달 유형은 수치 대신 미달 표기
- 동일 클립 내 인접 에피소드는 상관이 높음 → **에피소드 수를 독립 표본으로 세면 과대평가**. 유효 표본 수 산정 규칙 필요(§3.6)
- 층화 기준: 지역, 기상, 시간대, 도로 유형, 원인 유형

### 4.7 규칙 산출 가능성과 신뢰성의 분리

| 개념 | 내용 | 동결 여부 |
|---|---|---|
| `rule_derivable` | 규칙(CAN·3DOD·지도)으로 값 산출 가능 여부 + 소스 | 스키마와 함께 확정 |
| `reliability` | 그 규칙의 gold 대비 실측 정확도 | 동결 대상 아님 — 측정 후 필드별 기입 |

두 개념을 단일 불리언으로 혼용하면 **검증되지 않은 규칙이 채점 기준으로 승격**된다. `reliability` 미기입 필드를 기계 채점 기준으로 사용 금지.

## 5. 운영·메타 필드 — 단계별로 무엇이 기록되는가

**목적**: 산출물만 보고는 "이 라벨이 어떤 조건에서 만들어졌는지"를 알 수 없다. 나중에 필터링·오류 귀속·재현이 가능하려면 각 단계가 자기 흔적을 남겨야 한다.

| 단계 | 이 단계가 남기는 필드 | 없으면 생기는 문제 |
|---|---|---|
| **S0** | `key_frame_t`, 자차 거동(전이·결과 상태), `threshold_set_id` | 임계가 바뀌면 다른 데이터셋이 되는데 구분 불가 |
| **S1** | 후보 집합 전체, `physical_gate_passed`, `map_valid`·`map_dependent`, `fallback_path`, `camera_visible`, `window_truncated`, `window_start_reason`·`window_end_reason` | 후보 기록이 없으면 "후보에 정답이 없어 틀림(누락)"과 "있는데 잘못 고름(선택 오류)"을 구분 불가 |
| **S2** | 시각 판독 결과 전체(중간 산출물), `views_used[]`, `budget_profile` | 대상 모델의 뷰 집합과 불일치 시 달성 불가 기준이 됨. 예산 프로파일이 다르면 분포가 이질적 |
| **S3** | 인과 링크, 필드별 신뢰도, `none_source`, `unresolved` 사유 | 회피 경로 남용을 탐지 불가 |
| 공통 | `schema_version`·`generator_version`·`model_version`·`input_data_version` | 재현 불가 |

**핵심 규칙 3**

1. **무기록 fallback 금지** — 대체 경로(지도 실패 시 근사 등)로 만든 라벨이 정상 경로 결과와 구분되지 않으면, 품질 저하가 전체 평균에 희석되어 사라진다
2. **중간 산출물 영속화** — S2 출력·후보 집합·최종 귀속을 각각 보존. 최종 결과만 저장하면 오류 귀속 분리가 원천 불가
3. **이중 용도 분리** — 학습용(precision 우선)과 평가 분포용(recall 우선)을 두 벌로 만들지 않고, 위 플래그로 소비 시점에 필터

### 5.1 판정 범위 2단 (S1)

- **기록 범위**(넓게) ≠ **원인 후보 범위**(좁게). 기록은 소급 생성 불가한 정보를 보존하고, 후보는 판정 비용을 통제
- 기록 범위 내 검출 객체 전부를 후보 배열에 남기고, 물리 게이트 B 통과분만 인과 귀속 대상
- **범위 밖 = 미탐이 아니라 정의상 제외** — export 문서에 명시 의무

### 5.2 export 계약 (최종 산출)

- 품질 3등급: `rule_verified` / `human_sampled` / `unverified`
- **인과 라벨의 판정 근거 범위 표기**: 사후 정보(거동 완료 이후 구간) 포함 판정. 예측 모델 학습 용도 시 시점 제한 재라벨 필요할 수 있음
- 필수 동반 필드: `schema_version`·`generator_version`·`threshold_set_id`
- 미포함·조건부 제공 태그 목록 명시 (지도 의존 필드는 `map_valid=false` 클립에서 부재)

## 6. 입력 배치 — 프롬프트 블록 순서

### 6.1 왜 순서를 규약으로 정하는가

- **조건화 방향**: 모델은 각 위치에서 자기 앞의 토큰만 참조한다. 따라서 A를 B 앞에 두면 B의 내부 표현이 A에 조건화되고, 반대로 두면 조건화되지 않는다. 영상 토큰도 예외가 아니다 — 영상 앞에 놓인 텍스트는 영상 표현의 해석에 영향을 주고, 뒤에 놓이면 답변 생성 시점에만 제약으로 작용한다
- **연산 재사용**: 서로 다른 요청이 **앞부분 토큰이 완전히 동일**하면 그 구간의 계산 결과를 재사용할 수 있다. 한 토큰이라도 다르면 그 뒤는 전부 무효다. 어휘 정의가 1만 토큰이고 클립이 31만 건이면, 정적 블록을 앞에 두느냐 뒤에 두느냐가 총 연산량을 좌우한다
- 순서를 구현 재량으로 두면 위 두 효과가 통제되지 않은 채 버전마다 달라진다 → **규약으로 고정**

### 6.2 2단 재사용 구조

| 계층 | 범위 | 내용 |
|---|---|---|
| 전역 정적 블록 | 전 클립 공통 | system 지시 + 태그 어휘 + few-shot 예시 |
| 클립 프리픽스 | 한 클립의 전체 필드 질의 공통 | GT-before + 영상 토큰(창 전 구간) |
| 필드별 꼬리 | 질의마다 상이 | 대상 필드 지시 + 후보 목록 |

- 한 클립에 필드 질의를 여러 번 하므로, **클립 단위 프리픽스도 재사용 대상**이다. 영상 토큰을 필드별 텍스트보다 앞에 두어야 이 재사용이 성립한다

### 6.3 확정 배치 순서

```
━━━ 전역 정적 블록 (전 클립 동일) ━━━
[1] system 지시        태깅 역할·출력 규약
[2] 태그 어휘          축·값 집합 정의 (결정적 직렬화)
[3] few-shot 예시      시나리오 버킷별 고정 세트

━━━ 클립 프리픽스 (클립 단위 재사용) ━━━
[4] GT-before 블록     객체 목록 + 기하 (판정값 금지)
[5] 영상 토큰          시간창 구간 프레임

━━━ 필드별 꼬리 ━━━
[6] 필드 지시 + 후보    대상 필드와 값 후보
```

**규약**
- [1]~[3]에 **가변 요소 혼입 금지** — 클립 ID, 타임스탬프, 클립별 검색 few-shot, 무작위 정렬. 하나라도 들어가면 전역 재사용이 무효
- [2]는 **결정적 직렬화** — 키 순서·공백·소수점 표기 고정. 어휘 내용이 같아도 직렬화가 흔들리면 재사용 실패
- [4]에 S1 **판정값** 금지 — 위치·속도 등 관측 사실만. 판정값 주입은 채택하지 않음(DV-8)
- 어휘 변경은 [2]를 바꾸므로 전역 재사용이 전부 무효화된다 → **개별 반영이 아니라 릴리스 단위로 묶어 반영**하고, 변경 시점을 배치 경계로 기록
- **후보 자리는 프롬프트가 끝나는 지점에서 생긴다.** 값 확률은 필드 이름이 아니라 **위치**에 붙으므로, 어휘 정의를 프롬프트에 포함하는 것과 값 자리를 만드는 것은 별개다. 질의는 값이 시작될 지점에서 끊어야 한다
- **함정**: 모델에게 "각 값의 확률을 알려달라"고 지시하면 텍스트로 숫자를 써낸다. 그것은 모델이 생성한 문자열이지 실제 확률이 아니다. 확률은 서빙 API의 logprob 옵션으로 받는다

### 6.4 입력 예시

```
[1] 주행 영상에 사건 메타데이터를 부여한다. 지정된 값 집합에서만 선택한다.

[2] 태그 어휘 v0.4
    자차 세로거동: decel_onset | accel_onset | stop_initiate | launch | reverse_onset
    자차 가로거동: lane_change_left_onset | ... (전체 축 정의)
    원인 유형: agent | static_object | traffic_control | road_geometry | road_condition | ego_intent
    ...

[3] 예시 (버킷: 도심 교차로)
    입력 요약 → 출력 JSON 1건

━━━ 여기까지 전 클립 동일 ━━━

[4] 관측 객체
    id=17  종류=car        위치=전방 12.4m, 횡오프셋 0.2m,  속도 8.1m/s
    id=42  종류=motorcycle 위치=전방우측 9.8m, 횡오프셋 -2.6m, 속도 11.3m/s
    id=55  종류=pedestrian 위치=좌측 6.1m, 횡오프셋 -4.8m,  속도 0.0m/s
    (판정 없음 — 위치·속도만)

[5] <영상: 11.2s ~ 18.9s, 8프레임, 전방·전방우측 뷰>


[6] 질의: id=42의 방향지시등 상태
    후보: on_left | on_right | hazard | none | not_visible
```

- `rule_uncertainty` 임계 초과 객체는 [4]에서 제외하거나 "자동 검출값" 주석을 부착한다

### 6.5 다중 필드 점수화 실행

에피소드 하나에 채점할 닫힌 집합 필드가 여러 개이므로, 질의를 어떤 순서와 묶음으로 보낼지가 설계 사항이다.

**규모 (어휘 v0.4 기준)**

| 구분 | 필드 수 | 후보 합 |
|---|---|---|
| 세그먼트급 (자차 거동 4 + 원인 유형) | 5 | 32 |
| 객체급 (종류·위치·통제요소·기하 등) | 10 | 110 |
| 환경·시각 속성 | 약 16 | 약 90 |

- 객체 3건 에피소드 기준 **질의 약 35건, 후보 채점 약 360건**
- 채점 1건의 실제 계산량은 후보 접미사 토큰 3~6개뿐(앞부분은 캐시 히트) → 병목은 연산이 아니라 **요청 수와 캐시 경계**

**4단 질의 계획** — 필드 간 의존 구조에 따라 나눈다. 같은 단 안에서는 프리픽스가 동일하므로 한 번의 배치 요청으로 병렬 처리한다.

| 단 | 대상 필드 | 조건화 | 근거 |
|---|---|---|---|
| T1 독립 | 객체 종류, 위치(차로·방위), 환경, 통제 요소·상태, 시각 속성 | 클립 프리픽스만 | 서로 참조하지 않음 — 전량 병렬 |
| T2 종속 | 자차 거동 결과 상태, 객체 거동, 기하·노면 유형, 관련성 | T1 결과 포함 | 결과 상태는 전이에, 관련성은 위치·거동에 의존 |
| T3 결정 | 원인 유형, 인과 링크 | T1+T2 결과 포함 | 후보 평가 선행 필요 |
| T4 서술 | 자유 서술 필드 | T1~T3 확정값 포함 | 점수화 불가 — decode 1회 |

- T1 프리픽스 = 클립 프리픽스이므로 클립 내 재사용은 T1에서 최대
- T2·T3은 앞 단 결과가 붙어 프리픽스가 새로 생기나, 각 단 내부에서는 다시 공유됨

**필드 유형별 처리**

| 유형 | 예 | 처리 |
|---|---|---|
| 단일값 닫힌 집합 | 객체 종류, 위치 | 후보 K개 시퀀스 점수화 → 최댓값 |
| 다중값 집합 | 객체 거동(multi_ordered) | 조합 나열은 폭발 → **후보별 이진 채점**(존재/부재)으로 선형화. **순서는 모델이 아니라 계측 시각으로 결정** |
| 계층 필드 | 통제 요소 → 통제 상태 | 상위 확정 후 하위 질의 (T1 내부 2단) |
| 수치 | 계측값 전체 | 점수화 대상 아님 — 규칙 산출값 |
| 자유 서술 | 서술 필드 | T4 decode |

**실행 방식 — 3층 구성** (잠정. 실험 A로 확정)

| 필드군 | 처리 | 요청 |
|---|---|---|
| GT 필드(위치·거리·계측값) | 모델 호출 없음 | 0 |
| 의미 필드 대다수 | **생성 1회 → 결과 JSON 재프리필**로 전 필드 값 자리 분포 수집 | 2 |
| 판별이 갈리는 소수 필드 | 후보 시퀀스 채점으로 보정 | α (3~6) |

- 재프리필이 성립하는 이유: 값이 채워진 JSON은 **모든 필드 값 자리가 존재**하므로 한 번의 프리필로 전 필드 분포를 얻는다. 앞부분은 캐시 히트
- 유의: 재프리필 확신도는 모델이 스스로 쓴 값에 조건화된 상태의 값이다. "정답일 확률"인지 "자기 답에 대한 확신"인지는 gold 대비 calibration으로만 구분된다

**실행 시 주의 3**

1. **길이 편향** — 후보마다 토큰 수가 다르면 로그확률 합이 짧은 후보에 유리해진다. 후보 집합 내 **길이 정규화** 후 비교. 정규화 방식이 결과를 바꾸므로 실험에서 함께 고정
2. **캐시 경계** — 후보 구간이 캐시 블록 경계에 걸치면 해당 구간 확률이 재계산되지 않을 수 있다. 후보는 프롬프트 **말미에만** 배치하고 캐시 대상은 후보 직전까지로 한정
3. **신뢰도 척도** — 후보 집합 내 재정규화 확률을 사용하되, 생성 경로의 토큰 확률과 척도가 다름(§3.6 미결). 분포 엔트로피를 함께 기록

**조건화 강도와의 관계**: T2·T3의 조건화는 고정이 아니라 설계 변수다. weak로 두면 T1~T3을 전부 병렬 처리할 수 있어 지연이 크게 줄지만 필드 간 모순이 발생한다 → 실험 arm ④가 이 비교를 담당(§7.1).

## 7. 출력 순서 — 어느 단계 산물이 어떤 순서로 기록되는가

**목적**: VLM은 앞서 생성한 토큰에 조건화되어 다음 토큰을 만든다. 따라서 **출력 필드의 순서 자체가 추론 방향을 결정**한다. 결론을 먼저 뱉고 근거를 사후에 붙이는 구조를 차단하기 위해, 관측 사실 → 판단 → 결정 순으로 고정한다.

**본 파이프라인 특유 사항**: Action-first이므로 자차 거동은 VLM의 출력이 아니라 **입력 조건**이다. 출력 순서는 "확정된 거동을 설명하는 원인을 어떻게 좁혀가는가"의 순서가 된다.

| 순서 | 필드 | 산출 단계 | 성격 |
|---|---|---|---|
| 1 | `observed_agents[]` (후보별 시각 속성) | S2 | 관측 |
| 2 | `traffic_control_state` (신호·표지 상태) | S2 | 관측 |
| 3 | `road_context` (기하·노면) | S2 | 관측 |
| 4 | `environment` (맥락) | S2 | 관측 |
| 5 | `candidate_assessment[]` (후보별 관련성 + 신뢰도) | S3 | 판단 |
| 6 | `causal_links[]` (최종 원인 집합) | S3 | 결정 |
| 7 | `episode_confidence` | S3 | 결정 |

- **6번은 5번의 부분집합**이라는 제약을 자동 검증 항목으로 사용
- DV-7에서 2-pass(P1)를 택하면 **1~4 = Pass 1 파일, 5~7 = Pass 2 파일** — 순서가 곧 단계 경계와 일치하여 EPR 측정 지점이 파일 구조에 드러남
- 단일 pass(P2)를 택해도 동일 순서로 생성하되, 1~4와 5~7이 한 파일에 섞이므로 단계 분리 채점은 불가

### 7.1 신뢰도 배치

**필드별 부여** 확정.

- 필드 단위 calibration 산출이 가능해져 시각 인식과 인과 추론의 보정 상태를 분리 측정
- 대가: 앞 필드 신뢰도가 뒤 필드 생성에 영향 → 이 값은 절대 신뢰도가 아니라 **조건부 신뢰도**로 해석해야 하며, 해석 규약을 지표 정의서에 명시
- 오염 회피가 필요할 경우: 강조건화 pass(라벨용)와 독립 pass(보정 신호용) 이중 실행 — 필요성은 미결(§3.6)
- **조건화 강도 스위치**: 앞 필드의 확정값을 다음 필드 질의에 포함할지의 선택. 포함(strong)이면 필드 간 일관성이 오르고 오류가 전파되며 신뢰도가 조건부가 된다. 미포함(weak)이면 신뢰도는 깨끗하나 필드 간 모순이 발생
- 점수화 경로에서는 **공통 프리픽스로 복귀하는지 여부**만 바꾸면 되므로, 별도 호출 없이 스위치 하나로 두 모드가 등가 구현된다
- §7의 필드 순서 규약은 **strong 모드에서만 의미를 갖는다** — weak 모드에서는 순서가 결과에 영향을 주지 않음

### 7.2 파일 구조 이원화

- 어휘 JSON의 정의부는 **논리 그룹 순**(가독성), 생성 순서는 `generation_order` 배열로 **별도 명시**
- 순서 변경 실험 시 어휘 정의를 건드리지 않도록 분리

### 7.3 자유 추론 영역

`<think>` 자유 영역을 두는 경우, think가 이후 출력을 조건화하므로 **think 내용이 gold 채점 대상인지** 명시 필요 — 미결(§3.6).

## 8. 변경 관리 — 브랜치 기반 업데이트 규칙

파이프라인·어휘·프롬프트를 바꿀 때의 절차. **탐색은 자유, 정본 반영은 측정으로**가 원칙이다.

### 8.1 변경 등급

| 등급 | 대상 | 절차 |
|---|---|---|
| **불변** | 아래 §7.4 원칙 5개 | 변경 불가. 위반 코드는 병합 거부 |
| **좌표계** | 에피소드 정의(clip·episode·subject 구조), 어휘 축 구성, 앵커 산출 규칙, export 인터페이스 | 설계 회의 승인 + 기존 산출물 재처리 계획 동반 |
| **자유** | DV-1~7의 값, 하이퍼파라미터, 프롬프트 문구, 뷰 조합 | 브랜치 무제한 → 정본 병합 시 실험 결과 첨부 |

### 8.2 브랜치 규칙

- 브랜치에서는 무엇이든 시도 가능 — 단 §7.4 원칙은 브랜치에서도 적용
- **1 브랜치 = 1 변경 축** — 여러 변경을 묶어 병합하면 효과 귀속이 불가능해짐
- 정본 병합 요건: ① 변경 내용과 가설 ② 대조 조건(변경 전) ③ 동일 평가셋 결과 ④ 회귀 확인(기존 통과 항목이 깨지지 않았는지)

### 8.3 재현성 요건

**기록 대상 파라미터**

| 구분 | 항목 |
|---|---|
| 모델 | 체크포인트 해시, 토크나이저 버전, 연산 정밀도(dtype), 텐서 병렬 수 |
| 서빙 | 배치 상한(동시 시퀀스 수), 프리픽스 캐시 사용 여부, CUDA graph 사용 여부, 서빙 프레임워크 버전 |
| 디코딩 | seed, temperature, top_p/top_k, 최대 출력 토큰, 추론 경로(gt_only/scored/generated) |
| 입력 | 전역 정적 블록 해시, few-shot 버킷 ID, 프레임 수·프레임률·해상도·사용 뷰 |
| 데이터 | GT 버전, 어휘 버전, `threshold_set_id`, 배치 정책 버전 |

**주의**: seed 고정만으로는 불충분하다. 서빙 배치 크기와 프리픽스 캐시 히트 여부에 따라 부동소수점 합산 순서가 달라져 결과가 흔들릴 수 있다. 기존에 확인된 5-vote 비결정성의 원인 후보에 이 경로를 포함할 것

**검증 방법**

| 검사 | 방법 | 합격 기준 |
|---|---|---|
| 동일 조건 재현 | 같은 설정으로 회귀 셋 N클립 2회 실행, 출력 해시 비교 | 완전 일치 |
| 배치 민감도 | 배치 상한만 바꿔 재실행 | 불일치 발생 시 그 크기를 허용 오차로 문서화 (일치 강제는 성능 손실) |
| 캐시 민감도 | 프리픽스 캐시 on/off 비교 | 동상 |
| 매니페스트 완전성 | 기록된 파라미터만으로 타 노드에서 재실행 | 출력 해시 일치 |

- 임계 변경 = 데이터셋 변경 → `threshold_set_id` 갱신
- 서로 다른 버전으로 만든 에피소드를 같은 분포 분석에 혼용 금지

### 8.4 위반 금지 원칙 5

1. **앵커 비오염** — `key_frame_t`(전이 시점)와 종방향 거동은 규칙 산출. 모델 유래 값이 중간 경유로도 진입 금지. 경로 유형 라벨의 맥락 해소는 이 원칙의 예외가 아님(시점 확정 이후 단계)
2. **판정 근거 시점 표기** — 판정에는 창 전 구간을 사용한다(사후 정보 제한 없음). 산출물에 그 사실을 표기하여 예측 모델 학습 시 소비 측이 인지하도록 한다 (§2.4)
3. **순환 배제** — 규칙이 지목한 원인 후보를 프레임·뷰 선택의 조건으로 사용 금지
4. **무기록 fallback 금지** — 대체 경로 사용은 반드시 플래그로 기록
5. **필요조건과 정답의 구분** — 물리 게이트 통과를 정확도로 보고 금지
